M6 Findings — Does the DNA Transform Leave a Fingerprint?
M6 · Full Experimental Run

Does the DNA transform leave a statistical fingerprint—and does it survive encryption?

Both pipelines were run once, end-to-end, against all 6 frozen corpus files. Here is every test case explained on its own, using the real numbers from that run — plus the one finding that revised what this project believed earlier.

The setup

Two pipelines, one question

Pipeline A runs the DNA transform first, then classical AES-GCM encryption. Pipeline B skips the DNA transform entirely — it's the control, showing what AES-GCM alone looks like. Every test below measures something at one of these three checkpoints.

Test case 1 · Shannon entropy

How random do the bytes look?

Entropy measures how unpredictable the byte values are, on a scale of 0 (totally predictable, e.g. all zeros) to 8 bits/byte (perfectly random). Structured data like text or JSON starts low; already-random data starts near the ceiling.

Test case 2 · Chi-square vs. uniform

The sharpest surviving signal

Chi-square measures how far the byte-value distribution is from perfectly flat (uniform). Unlike entropy, it doesn't saturate near its ceiling — so it keeps separating structured data from random data even after entropy has mostly converged. Test case 5 · Avalanche effect

Flip one bit — how much of the output changes?

A well-mixed cipher should change roughly half its output bits when a single input bit flips. But where you measure this matters enormously — measuring after AES-GCM mixes in a brand-new random "nonce" every single time, which by itself makes any two encryptions look ~50% different, flip or no flip.

Test case 7 · Size overhead

How much bigger does encryption make the data?

AES-GCM's ciphertext body is always exactly the same length as the plaintext — it's a stream cipher underneath, no padding. The real overhead is the 16-byte nonce and 16-byte tag that travel alongside it. Measuring only the ciphertext body, as the literal spec first suggested, produces a flat, meaningless zero.

The most important finding

A correction: the real entropy gap is smaller than first believed — and here's exactly why

Early in this project, a hand-built test sample and a hand-picked 64-nucleotide reference sequence suggested a ~0.6–0.7 bits/byte gap between text and random data. M6 is the first time the pipeline ran against the real, frozen 61-nucleotide reference sequence — and the real gap is far smaller.

Confirmed, not just noticed

Swapping the real corpus through the old reference sequence reproduces the bigger 0.22-bit gap. Swapping the old sample text through the real reference reproduces the small gap. The reference sequence — not the corpus, not a bug in the transform — is what drives the difference. This is a real, reproducible, mechanistically-understood correction, not a defect.

Bottom line

  • Yes, there's a real signal. The DNA transform alone leaves text and JSON measurably different from random — small on entropy (~0.05–0.10 bits/byte), much clearer on chi-square (4.8–8.4×) and compression ratio.
  • Yes, it disappears once AES-GCM runs. By post_classical, Pipeline A is statistically indistinguishable from Pipeline B on every metric, for every data class — exactly what a correctly-functioning classical cipher should do.
  • The magnitude needed correcting, not the conclusion. M1's original ~0.6–0.7 bit figure used a sample reference sequence the real pipeline never actually ran with; the real number is smaller, and now fully explained.
  • Two measurement traps were caught and fixed along the way: avalanche testing that only detected AES-GCM's nonce noise, and size-overhead that was mathematically fixed at zero — both now measured correctly, on real data, in the same table.
